# 0.9.0 验证范围

本轮使用虚拟 P90（设备型号 emulator）及独立包 `com.szk.dshconnect.qa`，不读取/导出生产包的历史，不调用付费模型。SDK 原生编译通过不等于运行时全部 API 可用。

## 已发现并修复

原生系统 PDFKit 在当前模拟器运行时没有提供，直接创建 PdfDocument 失败。导出改用 ArkUI Canvas 生成的 RGB JPEG 页面和本地 PDF 1.4 写入器，按字节计算交叉引用和流长度；不解析外来 PDF，不使用网页或远程转换服务。格式依据 [ISO 32000-1](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf)。

## 导出及界面

- 虚构中文对话包含 110 行长路径表格、代码、图片和尾部标记，生成 2 段 PNG、Markdown 和 12 页 PDF。PDF 使用独立读取器严格读取，并渲染全部页作视觉检查；中文、图片、页序、页脚与末尾内容正常。长表格允许跨页续行，PDF 文字为栅格图像。
- 主页、独立聊天、图像工作室及 DSH 连接页截图已检查：浅色状态下系统栏和页面底色一致，无 DSH 全页黑底；保留按钮自己的系统材质，不给整条标题栏加材质。
- QA 包与生产包 Bundle ID 分开。编译脚本在 finally 恢复生产清单和入口；测试页不进入生产包。
- 原生交互回归通过：首次完整回复后自动命名一次，第二次提问没有重复命名；模拟服务报告两次回复与一次命名共 324 Token，弹窗统计相符。独立聊天与 DSH 导出菜单均能打开。

## 发送插件

在隔离目录安装官方 Cordis 4.0.5、dsh-commands 和 dsh-session 0.2.1-rc.2，实际完成插件注册、执行、Session 的 command/run + command/done 日志及注销。发送正文没有重复到 command/run.args，原版固定 Desktop bridge 的历史接口可返回结果，鸿蒙解析器能显示独立消息。没有调用 Agent 模型，没有引入未知 Session 事件。

虚拟 P90 的隔离原生包已通过现有二维码连接该固定上游桥接，并经 SSE 收到发送命令结果，渲染为可复制正文。Host 端仍为虚构会话，不代表用户的完整桌面环境已验收。

`npm run check` 覆盖解析、连接策略、协议、用量、命名、导出分页和 PDF 偏移等。官方服务集成测试使用 `npm run verify:sender`，依赖需事先按脚本注释安装到隔离目录。

自动命名验收还发现 Chat Completions 请求缺少标题系统指令，曾误用普通回复首行；已补入专用 system 消息并保留各协议原生指令字段。命名请求也继承用户的用量开关。

## 实际限制

没有本版本 Mate 90 真机验收；物理机启动器的缩放动画、智感握姿和原生材质仍需真机检查。没有实测真实付费 API、真实公网隧道或完整 DSH Desktop 插件安装 UI；隔离服务测试不是全桌面 UI 验证。图像工作室未取得统一的服务端 Token 账单，DSH 只提供正文估算。PDF 没有可选择的文字层，AI 元数据合规及正式发布资质仍未完成。

未上架鸿蒙商店，未提交市场 PR，未声称无漏洞或所有供应商全面兼容。正式发布差距见历史评估 `RELEASE_READINESS.md`；本轮导出增加了可见 AI 标识，但不能据此认定完整标识合规。
