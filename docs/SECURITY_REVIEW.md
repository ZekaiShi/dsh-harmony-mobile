## 已核对的安全边界

- 配对 token/PIN 不进入最近记录和日志；DSH Cookie 与模型 API Key 使用不同 Asset Store 命名空间，按规范化 origin 隔离。缓存 JSON 不包含这些凭据。
- HTTP 不自动跟随重定向；跨 origin 配对迁移先确认。模型与图片请求不带 DSH Cookie；CDN 图片请求不附模型授权。TLS 使用系统证书验证。
- 模型请求直接发给用户配置服务；图片、文件、最近 40 条有效消息随发送进入上下文，后续追问可能重新上传附件。该客户端没有自建聊天中转、广告或统计 SDK。
- 相册与文档通过系统选择器导入，缓存文件名严格限定在应用私有目录；图片大小/像素、附件大小/类型和缓存额度受限。服务返回的图片先解码验证，再显示本地缓存。
- 消息使用 ArkUI 文本渲染，不执行 HTML/脚本；电脑文件引用只展示/复制路径，不打开手机任意文件或执行命令。独立聊天没有手机端工具执行能力。
- manifest 仅申请 INTERNET 和 DETECT_GESTURE；没有后台常驻、通讯录、定位或全盘存储权限。握姿状态仅在内存、前台监听，不上传。

## 必须保留的限制

1. **局域网 HTTP 仍是明文。** 为兼容上游二维码保留；同一不可信网络中的窃听/中间人风险没有消失。安全远程访问应使用 HTTPS 隧道。未实现证书固定或 LAN 端到端加密。
2. API Key 按 origin 而非 URL 路径隔离；同一域名不同路径共享密钥槽位，这是现有设计。仅使用可信服务地址。所选服务会接收实际提示词、上下文和附件，其保存/训练政策由服务提供方决定。
3. 本地历史/草稿/附件在应用沙箱中，未增加独立文件加密。root、已授权调试或被攻陷设备不属于安全保证范围；当前 debug HAP 可调试，不能作为商店发行版。
4. 图片 URL 下载不附密钥，但仍由模型服务指定目标。尚未实现 DNS 解析级本地网络阻断或逐主机确认；使用不可信服务的风险需在发行前决定防护策略，不能把“无密钥”解释成任意 URL 都安全。
5. 未覆盖所有 SDK/系统版本、真实供应商、真实公网隧道、摄像头实际识码、长时间压力与畸形图片模糊测试。原生库漏洞、持续海量合法事件导致的性能压力仍需发行前测试。
6. 本地 `build-profile.json5` 含 Studio 的开发签名配置，供本机使用。**不要直接对整个工作目录 git add。** 经检查的源码 ZIP 已清空 signingConfigs 并去掉产品 signingConfig。旧源码 ZIP 保留作内部历史，不能沿用本轮检查结论。
7. 开发验收环境只放虚拟数据；上游原样的移动桥会监听本机所有网卡，部分开发 fixture 也用于模拟器网络。运行时应在隔离网络中使用，用完关闭；这些 Node 工具不进入 HAP。

以上是人工代码审查、公告扫描和定点回归的结果，不是第三方渗透测试报告或安全认证。
