# 页面与握姿动效规则 · 0.8.4

## 点击反馈

1. 进入新页面使用原生导航 push，开启系统转场；中文界面从右侧进入。返回通过同一个导航栈 pop，使用反向系统转场。不得通过直接修改 screen 后替换页面分支来代替导航。
2. 独立聊天的设置、新对话、历史对话、服务商、模型选择、上下文设置、隐私页，图像工作室的设置、模型选择、历史、详情、预览，均为 NavDestination。DSH 沿用独立 Router 入口与原生内部导航；在聊天中创建新会话也使用 push。
3. 保存设置、选定模型是返回来源页，使用反向 pop；返回时优先找到最近的同名父页，避免多个对话之间返回到更早的设置来源。PIN 成功后替换为会话列表，不保留已完成的密码页。
4. 不产生新页面的操作使用相应原生反馈：按钮按压、菜单展开、选择高亮、对话框或加载状态。不要为了“每次点击都有反馈”给复制、选择选项等操作强行推入空页面。

Assistant 与 Media 通过共享 PageNavigation 控制页面栈；项目接线检查限制 screen 赋值只能出现在 forward / returnTo 两个路由函数内。导航单元测试覆盖重复设置点击、强制新对话、最近父页和失效父页恢复。

## 握姿切换

- 左手时：独立聊天的加号位于输入框外左侧，发送/停止位于框内左侧。右手时，两者一起切至右侧。电脑聊天发送/停止采用同样的缓动。
- 加号、输入框横移、发送与工具信息区读取同一个 composerSide，使用 UIContext.animateTo 驱动，持续 380 ms，曲线 cubic-bezier(0.4, 0, 0.2, 1)，起步加速、到位减速。不使用 JS 逐帧计时器。
- 加号左右换边时使用独立 offset 属性上浮再落下，峰值 56vp；原生 keyframeAnimateTo 分两段 190 ms 完成，顶部速度归零，避免和发送按钮在中间重叠。水平 translate 与垂直 offset 分开，避免同时对同一属性施加两个动画。
- 发送与附加操作通过同一个 ComposerToolbar 排布，输入框保持同一 TextArea 节点，不因左右切换重建、翻转文本、清空草稿或主动收起键盘。首次显示直接定位到当前握姿，不播放初始化换边。
- 重复选择当前手动模式不重订阅传感器；相同握姿不重复发布布局状态。自动握姿沿用既有防抖、前台订阅和后台解除，不增加传感器权限，不上传或保存握姿状态。

## 验证边界

78 项核心/导航测试和官方签名编译通过。遵循用户选择，本轮未操作手机，也没有验证真实握姿传感器、键盘焦点、实际动画帧率或最终视觉手感；这些仍由支持设备验收。不得将编译通过写成已经达到某个帧率或无条件保证流畅。
