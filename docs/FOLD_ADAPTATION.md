# 0.10.0 折叠屏与窗口比例适配

## 布局规则

使用 ArkUI 当前窗口的 vp 宽高，持续响应 onSizeChange。没有按机型名称或物理像素指定固定布局。折叠、旋转和键盘只更新布局指标，不重新创建会话、路由栈或网络客户端。

| 可用宽度 | 主页 | 聊天 |
| --- | --- | --- |
| 小于 600vp | 单列入口，可滚动 | 单栏 |
| 600–699vp | 双列入口 | 单栏 |
| 700–959vp | 双列入口 | 240vp 会话侧栏与正文 |
| 960vp 起 | 三列入口 | 280vp 侧栏与正文 |

正文最多 820vp；设置、模型列表、历史及重命名表单最多 760vp 并居中；配对设备页和 PIN 表单分别限制 640vp、520vp。正文、表单和标题栏保留各自的滚动与系统安全区。高度小于 520vp 时减少输入区和主页纵向间距；可用高度小于 300vp（例如外屏横向弹键盘）时，聊天页暂隐标题栏、辅助工具行和附件缩略条，保留原输入组件与发送按钮。收起键盘后恢复这些区域，草稿和附件不变。

图像作品按实际容器宽度排成 1/2/3 列，保持原图比例，可独立预览。聊天中的宽表格继续横向滚动，不挤压整页。宽屏侧栏切换会话替换当前聊天目的页，返回仍只有一层会话页。

折叠不改变当前会话、附件、未发送输入或配对身份。布局分支只影响显示；独立聊天与 DSH 各自沿用原有保存和通信逻辑。

## 设备与系统边界

参考华为公开规格，而非据此宣称真机实测：

- [Mate X7](https://consumer.huawei.com/cn/phones/mate-x7/specs/)：内屏 2416×2210，外屏 2444×1080。
- [Pura X Max](https://consumer.huawei.com/cn/phones/pura-x-max/specs/)：内屏 2584×1828，外屏 1848×1264。
- [Mate XT 非凡大师](https://consumer.huawei.com/cn/phones/mate-xt-ultimate-design/specs/)：单屏 2232×1008，双屏 2232×2048，三屏 2232×3184。

安装最低版本设为 HarmonyOS 6.0.0/API 20，编译目标仍为 API 26。API 26 的沉浸材质调用以稳定的 sdkApiVersion 检查保护，低版本保持普通系统圆形按钮，不在低版本调用 API 26 引入的 apiAvailable。当前可用模拟器均为 API 26；最低版本设备运行仍需补测。旧三折叠机出厂 HarmonyOS 4.2 不能直接运行原生 HAP，必须先具备相应原生鸿蒙系统支持。

## 可复现检查

1. `npm run check` 检查窗口策略边界与现有核心逻辑。
2. 官方 SDK 执行 `npm run build:hap`。
3. `node tools/build-export-qa.mjs` 构建独立 `com.szk.dshconnect.qa`，不会读生产沙箱。
4. 在已安装隔离包的模拟器上执行 `HDC_TARGET=127.0.0.1:<端口> node tools/verify-fold-layout.mjs`；三折叠额外指定 `FOLD_KIND=trifold`。PowerShell 用 `$env:` 设置变量。

测试使用虚构本机会话、离线生成的三张不同宽高比图片，以及上游手机桥的本地虚构 DSH 工作区。不访问真实历史和付费模型。截图、布局与详细报告只存放在忽略的 `.cache/`、`reports/` 中。系统材质折射、真实折痕、握姿传感器与铰链表现需要实体设备验收。
